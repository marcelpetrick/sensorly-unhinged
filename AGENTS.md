# AGENTS.md — Working agreement for this repository

This file is the contract for every contributor, human or agent, working on
**sensorly-unhinged**: a battery-powered ESP32 + temperature/humidity sensor node,
developed as two physical variants (A compact / B thermally isolated) from **one**
electrical platform.

Read this before touching anything. It is short on purpose.

---

## 1. What this project is

A **hardware** project first, firmware second. The deliverable is not "a PCB that
works" — it is a *repeatable, manufacturable, measurable* platform:

- one schematic → two board layouts → two enclosures → 5 + 5 prototypes,
- a quantitative A/B thermal experiment,
- one revised design → a controlled 20-unit series.

Design history is a first-class artifact. If a decision cannot be reconstructed
from the repository, it was not made properly.

---

## 2. Non-negotiable engineering rules

1. **One electrical platform.** A and B share the schematic, netlist, BOM and
   firmware. Only geometry, thermal isolation and enclosure differ. Any change
   that forks the electrical design must be raised as an ADR first.
2. **Measure before you transmit.** Firmware reads the sensor *before* the radio
   is powered. This is an accuracy requirement, not an optimisation.
3. **The enclosure is part of the instrument.** Vents, chambers and the sensor
   island are design deliverables, not packaging.
4. **Nothing is "locked" unless `docs/30-electrical-design-spec.md` says so.**
   Open decisions live in the "Open" table with an owner and a closing gate.
5. **No magic numbers.** Every component value in the schematic traces to a
   datasheet page, a calculation, or an explicit assumption written down next to it.
6. **Second sources or it does not ship.** Every BOM line carries at least one
   alternate, or an explicit "single-sourced, accepted risk" note.

## 3. Tooling — open source, scriptable, reproducible

| Purpose | Tool | Notes |
|---|---|---|
| Schematic / PCB | **KiCad 9+** (`kicad-cli`) | canonical source of truth is the `.kicad_sch` / `.kicad_pcb` text |
| Board geometry | `tools/boardgen/` (Python) | parametric generator: **A and B are emitted from one model** |
| ERC / DRC / outputs | `kicad-cli` via `make` | never click-and-export by hand |
| Enclosure | **OpenSCAD** / **FreeCAD** | parametric `.scad`, board STEP imported |
| Firmware | **ESP-IDF** | not Arduino, for the production firmware |
| Docs | Markdown + SVG | no binary office formats in git |
| Diffs | `kicad-cli sch export` / `pcb export svg` | rendered artifacts are regenerated, not hand-edited |

**Rule:** if a step cannot be run from `make`, it is not part of the build.
Generated files (`hardware/outputs/**`, `docs/img/*.svg`) are committed *and*
reproducible — CI regenerates them and fails on drift.

## 4. Repository layout

```
docs/            requirements, specs, trade studies, ADRs, test plans
hardware/
  lib/           project symbol + footprint libraries (vendored, verified)
  schematic/     one schematic, generated, shared by both variants
  variant-a/     compact board            (HW-A1)
  variant-b/     thermally isolated board (HW-B1)
  outputs/       generated gerbers/drill/BOM/CPL/STEP  (regenerated by CI)
tools/boardgen/  parametric board generator (single source for A and B)
mechanical/      OpenSCAD enclosures, one per variant
firmware/        ESP-IDF application
production/      test fixture, flashing + factory-test scripts
measurements/    raw A/B thermal, battery and RF data
```

## 5. Git workflow

- **Conventional Commits**, mandatory:
  `feat|fix|docs|refactor|test|chore|ci|build(scope): imperative summary`
  Scopes used here: `hw`, `sch`, `pcb-a`, `pcb-b`, `boardgen`, `mech`, `fw`,
  `prod`, `docs`, `ci`.
- **Atomic commits.** One reviewable idea per commit. A commit that touches the
  schematic *and* renames files *and* fixes a typo is three commits.
- Regenerated sources go **in their own commit** where practical, referencing
  what caused the change.
- Never rewrite published history. Never `--force` onto a shared branch.
- Hardware revisions are tagged: `hw-a1`, `hw-b1`, `hw-b2`, … and the revision
  string is printed on the silkscreen. `final.zip`, `final2.zip` are banned.

## 6. Definition of done for a change

A change is done when:

- [ ] `make erc drc` passes: zero ERC violations, zero DRC errors, zero
      schematic/PCB parity differences (or the waiver is in the commit message),
- [ ] generated outputs regenerate byte-identically,
- [ ] the affected `docs/` section is updated in the *same* commit,
- [ ] any newly locked decision moved from the Open table to the Locked table,
- [ ] a reviewer can see *why* from the commit message alone.

## 7. For AI agents specifically

- **Do not invent datasheet numbers.** Cite the source (datasheet + section, or
  URL) next to any figure you introduce. If you are unsure, write `TBC` and add
  it to the open-questions table — a wrong number in a spec is worse than a gap.
- **Do not silently widen scope.** Rev 1 has an explicit non-goals list
  (`docs/10-requirements.md` §Non-goals). Respect it.
- **Prefer generating over hand-editing** KiCad files: change
  `tools/boardgen/`, re-run, commit both.
- **Both variants move together.** A change to placement, netlist or rules that
  applies to A must be considered for B in the same change. State explicitly when
  it deliberately does not.
- Footprint/pin-1/rotation errors are the highest-consequence mistake available
  in this repo. Verify against the datasheet land pattern, every time.
